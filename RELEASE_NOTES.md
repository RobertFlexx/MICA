# MICA 1.0 release notes

Date: October 16, 2026

This is the first broad MICA research SDK. The ISA is experimental and the physical core has not been brought up on an FPGA. Version 1.0 describes the SDK package, not a claim of production silicon readiness or that performance exceeds RISC-V.

## Software and architecture

- New `F` flow extension: compact post-incrementing byte, halfword, word and quadword memory instructions, extended signed-stride operations, and `dbnz` counted branches. Encodings and exact 32/64-bit behavior are in `docs/ISA.md`.
- C++23 assembler and functional emulator implement `F` in both 32-bit and 64-bit modes. A C++23 `mica-dis` tool decodes raw binaries.
- Existing compact opcodes and basic assembler syntax are retained. Regression tests exercise selected original v0.1 encodings.
- Freestanding assembly library added for flow copies, memory scanning/swapping, string comparison, CRC-32 and bounded arena allocation. These routines are not a hosted C standard library.
- 31 end-to-end software integration tests pass on the development host, including randomized math, known CRC-32 answers, 32/64-bit memory operations and invalid-instruction handling.

## RTL and board

- Scalar multicycle RTL now includes `F` decode and execution logic for MICA-32 and MICA-64. Testbench source exists, but an HDL simulator was unavailable in the release environment. **No RTL testbench has actually been executed here.**
- Arty A7 top-level port map, pin constraints, UART TX and LEDs, and generated byte-ROM images. FPGA timing closure, bitstream generation, electrical verification and hardware bring-up remain unperformed.
- Eight new paired Graphviz source, SVG, and PNG diagrams. The current system is separated from unimplemented scalable multicore and power-domain research drawings.

## Performance study

The simple scalar byte-copy inner loop is 12 encoded bytes (six 16-bit instructions). `F` reduces this sample to eight bytes (two 16-bit instructions and one 32-bit instruction). This is 33.3% fewer loop-body bytes and 50% fewer instructions in the sample, with no claim about clock frequency, heat or energy. The data is reproducible using `python3 benchmarks/flow_density.py`.

## Next hard gates

Execute HDL simulation, formal instruction equivalence against the emulator, synthesize and close timing on an actual FPGA, replace combinational read RAM with a synchronous memory protocol, and measure energy per completed workload against comparable open RISC-V cores. Then build a stable ABI, linkable object format and compiler backend. Do not treat a proposed multicore or DSP block as available hardware yet.

## Build

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
python3 benchmarks/flow_density.py
```
